01 · 延长线

把现有 DSpark 做快

沿当前推理链路量化草稿、验证和搬运，再选最小的改动验证。

DSpark 每轮的收益来自哪里

投机解码用一轮较便宜的草稿加一轮目标验证，换取一次提交多个 token。DSpark 的草稿骨干并行生成各位置的基础 logits，再用轻量 Markov 模块串行加入前驱 token 的条件偏置。置信头估计候选前缀的接受概率，调度器据此选验证长度。DSpark 论文

  1. 草稿　已提交前缀接出三个候选 A B C。基础 logits 并行计算，条件偏置沿候选链逐位更新。
  2. 验证　目标模型根据各位置的候选前缀并行计算。以 greedy 为例，目标接受 A，随后在 B 的位置选择 X。
  3. 提交　本轮输出 A X。丢弃被拒草稿及其后缀，按接受边界更新目标状态，对齐下一轮的输入。
用每个最终提交 token 的耗时判断收益

将解码计时窗口内的墙钟时间除以实际提交 token 数，包含草稿、元数据构造、主机同步、验证和状态提交。增加验证位置时，同时看它增加的预期提交量和实际多出的设备工作。

上游反例　vLLM-Ascend #21137 作者在 A3、TP4／DP4、混合 P/D、并发 10 的对照中，自适应 eager 取得吞吐收益，自适应 graph 三轮均低于固定预算 graph。复测时把两种模式分开，观察逻辑验证行、设备实际行和 padding。Ascend 自适应验证 PR

Trace 的主要耗时先试的改动要验证的收益
串行 Markov 打分 保留单条候选链和目标验证，对照完整转移打分、base top-k、base top-k 合并前驱条件候选。vLLM DSpark 实现 先用 greedy，比较完整草稿 top-1 召回、接受长度和每提交 token 的耗时。完整投影之后收集候选，只能归因后续算子；base LM head GEMM 仍应单列。
元数据或搬运 逐项检查 slot／page 映射、位置、长度张量、logits／state 拷贝和 D2H 同步。优先复用缓冲区与已有长度镜像。标签版源码 记录减少的 kernel launch、同步次数、字节和峰值工作区。覆盖抢占、异长请求、部分拒绝与全部拒绝，检查输出 token 和状态等价。
验证行与图 padding 扫固定预算并构建本机曲线，再试按置信度共享验证行。MRV1 复用 DynamicSpecScheduler，MRV2 单独核对自适应验证的配置及图约束。Ascend 标签版文档 按并发、目标 GDN／attention、TP 与执行模式观察实际行数。逻辑行已经减少但设备仍跑原尺寸时，下一步查 shape 分桶和图分派。

下一处瓶颈取决于验证对象

  1. 等待目标特征。 D3D 在验证当前草稿时为可能的后继准备草稿，减少对刚产生的目标隐状态的串行依赖。论文的 Qwen3-8B 作者实验相对 AR 的平均解码加速为 5.00×，其 DFlash 对照为 4.03×。复测要将等待时间、未走分支的工作量和共享设备带宽分别计入。 D3D 论文 · 作者代码
  2. 目标特征编码不足。 W47 提交的 DNeo 用 MoFA、拒绝历史与非均匀特征 tap 改善并行草稿。论文相对 DFlash2 报告约 1.3×，收益对应作者配置。用相同 drafter 参数规模对照连续接受长度和每轮草稿时间。 DNeo v1
  3. 目标本身是扩散语言模型。 SPOT 预测掩码位置的提交顺序，目标验证的是包含位置、token 与顺序的状态转换。W47 扩展版引用的 v1 报告最高 3.2× 吞吐，v2 在新硬件上重跑的 SDAR-8B 对照报告最高 3.4×。原型固定提交规则，用逐步重放对照状态，比较目标前向次数和任务质量。 SPOT v1 · SPOT v2 · Trajectory-Level SD

共同实验门槛 用一套 Qwen3-8B 轨迹先固定 tokenizer、输入、输出上限、精度和停止规则。分开呈现同一引擎内的 A/B 和跨引擎的工程对照。覆盖单请求及接近饱和的并发，记录每提交 token 耗时、接受分布、实际验证行、P95 TPOT 和任务达标吞吐。扩散目标在自己的逐步去噪基线内比较。复现结果为 pending_remote。

03 · 新方向

从相关方案到独立选项

先看循环模型、投机和缓存如何组合，再按不同业务瓶颈判断各独立方向的投入时机。

相关方向 · 复用权重，再按成本分配计算深度

循环 Transformer 把一部分深度做成可重复执行的共享层。它和投机解码可以组成一个可检验的假设：用较浅的计算生成候选，完整深度按原语义验证，比较每个成功任务的耗时、读取量和设备成本。

架构信号 · GLM-5.4

从约 750B GLM-5 基座继续训练，中间 28 层的同一组参数执行两遍。每遍用独立的 token 门控更新残差。第二遍复用第一遍的稀疏索引和历史 KV，另保留自身的局部滑窗 KV。权重存储可复用，第二遍仍有注意力、KV 读取和层计算。

开放入口 · Inkling 与 LoopCache

Inkling 2 Mini 的三遍固定深度在每遍保留独立 KV 与卷积状态，公开 DSpark 以多遍隐藏状态为输入。可变循环研究版支持后遍覆盖的 KV 共享，卷积状态仍各自保留。单 GB200、TP1、4K、batch 1 的作者仅前向对照，三遍共享后 KV 容量 175K → 194K token，decode step 3.85 → 3.86 ms。

独立方向 · 用流量画像选服务侧项目

先看实际请求由重算、排队、通信、容量还是 head 主导。相同的加速倍率对不同负载有不同价值，业务 SLO 和设备数固定后再比较。

方向什么时候投先做哪条实验加码或停止
会话回放与差分基线同时在评估引擎、缓存、量化或投机，性能收益容易与输出变化混在一起。固定回放保留 token IDs、到达间隔、工具暂停和分支；动态任务按真实生成结果执行，检查任务成功。先用 20–50 条会话建立可诊断样例，再扩大样本估计尾部。输出首个分歧、阶段时序和任务级达标产出。
AIPerf · MLPerf Endpoints 方法
前缀路由与 host KV多轮 Agent／RAG 前缀重叠明显，重复 prefill 或热点副本排队占比高。同卡数四臂对照：负载均衡、前缀感知、加排队权重、加 host KV。按租户看命中 token、读回和回退重算。报告建议用任务 goodput +10% 或 P95 TTFT −15% 作试点门槛，并检查低命中组与最慢租户。host 读回持续慢于重算时结束第二层。
llm-d 负载差异
Ascend P/D 与上下文并行有固定 A3/A5、目标模型和长上下文工作负载，长 prefill 明显干扰 decode。同芯片和卡数比较聚合、PCP、P/D；按所用版本核对 DCP/connector 组合，并测状态传递、网络交接和抢占恢复。同 NPU 小时下联合 TTFT／TPOT SLO goodput 提升才扩大。遇到跨节点传输挤占 TTFT 时，先检查按长度路由和同置方案。
上下文并行 · TaiChi
稀疏索引与低精度 KV已拆出主 KV、索引缓存与临时缓冲，确认某项容量或读取带宽触顶。相同 top-k 语义记录 scorer、gather、反量化和 attention。先用已支持的 FP8/C8 配置验证容量，定位后再试索引压缩或 offload。依赖长文本检索和任务质量门槛。公开 GB300 稀疏 MQA 的 512K 单层 14–23× 对应整模型 decode 3–6%，因此分别验 kernel 和端到端。
vLLM 内核拆解 · Twindex
小标签评分与 LM head固定单 token 标签评分占相当流量，热缓存下投影、跨 TP 规约或 D2H 仍显著。比较全词表计算＋小结果、原生 score、候选条件评分。先核对模板、tokenizer、标签及 x_label_mass 等合同。全词表概率需要原归一化，候选内 softmax 是另一语义。端到端占比小则回到 prefill 或队列，让问题/s 和完成时延决定投入。

评审需要看到的三份证据

第 1–3 天 · 基线

冻结引擎、权重、精度、并行、停止和负载。抓首处分歧及阶段时序，确认冷／热、低／高并发真实路径。

第 4–8 天 · 单变量对照

重复同一 trace。展示真实执行形状、首字与 token 间延迟，额外记录失败、重试及画面外的系统开销。

第 9–10 天 · 外部样本

用独立样本复测，提交收益区间、失败流量及回退条件。达到同质量和 SLO 门槛后进入集成验证。

看两类指标。 每提交 token 耗时和实际验算行数用于归因。任务成功率、任务时间和每卡达标产出用于投入决策。上游数字与自身复测分列。
